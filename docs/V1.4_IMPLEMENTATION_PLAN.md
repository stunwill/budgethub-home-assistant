# Fynvo v1.4.0 Implementation Plan

## Objective

Improve mobile usability, navigation consistency, financial record presentation, chart readability and CI/migration reliability without changing established financial behaviour.

## Confirmed repository baseline

- v1.3.0 is merged into `main` via PR #32.
- `AppV13.jsx` renders a global fixed `v11-launcher`, which is the bottom panel obscuring mobile content.
- Cash-flow visualisation is still implemented as custom SVG charts.
- Recurring Expenses already has a compact dedicated responsive presentation in `CorrectiveV0174Pages.jsx`.
- Bills, Income and Accounts still rely on older generic page rendering.
- The backend migration chain is currently composed by wrapper reassignment in `app/__init__.py`, including a final v1.3 wrapper.
- Schema version 13 is currently hard-coded in migration/test expectations.

## Delivery sequence

1. Replace the global fixed launcher with normal navigation access to Cash Flow Intelligence, Household, Data Coverage, Split Transaction, Security & MFA and Data Export.
2. Introduce reusable v1.4 financial record presentation components and apply them to Bills, Income, Accounts and Cards where appropriate.
3. Replace/improve the forecast chart with a bundled frontend chart dependency if it provides better responsive/touch behaviour. Do not depend on HACS runtime assets.
4. Investigate Category integrity findings and repair only demonstrably safe defects while preserving linked history.
5. Add one authoritative current schema-version definition and explicit ordered migration orchestration.
6. Keep v1.4 tests additive and preserve established regressions.
7. Align add-on/backend/frontend versions to 1.4.0 and update release documentation.
8. Run CI-equivalent validation and keep the PR draft until all automated checks are green.

## Manual acceptance gates

Installed Home Assistant ingress and representative iPhone/mobile behaviour remain manual release gates where repository CI cannot reproduce the installed environment.
